# 로그 검색 보기

2026-10-28 프론트 검색·필터 구현 기준. 기존 실시간 보기는 기본값으로 유지한다.

## 화면과 데이터 흐름

검색 보기로 전환하면 SSE 연결과 실시간 만료 타이머를 중단한다. 기간(UTC, 최대 24시간), 서버, 단일 레벨, 메시지 조건을 편집하고 조회 또는 Enter로 적용한다. 입력할 때마다 요청하지 않는다. 검색 결과는 조회 시점의 고정 목록이며 자동 재조회하지 않는다. 실시간 복귀는 새 snapshot을 받아 연결한다. 검색 결과로 SSE cursor를 만들지 않는다.

브라우저 → Next.js `/api/logs/search` → 백엔드 `/api/v1/logs/search` → ES 순서다. 백엔드 주소를 브라우저에 노출하지 않는다. 상세는 기존 MySQL 상세 API를 사용한다. 검색어를 URL이나 영구 저장소에 기록하지 않는다.

메시지는 Nori 단어 분석 후 AND 검색이다. 단순 부분 문자열·구문·예외 원문 검색은 아니다. 프론트에서 문자열 포함 검사로 결과를 다시 거르지 않는다. 공백 검색어와 전체 서버·레벨은 선택 조건을 생략한다. 메시지 최대 200자는 Unicode 코드 포인트로 계산한다.

서버 선택지는 현재 구성인 was-1, was-2, was-3이다. 현재 표시된 로그에서 서버 목록을 추출하면 로그가 없는 서버를 선택할 수 없으므로 설정 상수를 사용한다. 동적 서버 메타데이터 API와 구성 변경은 후속 합의 대상이다.

## 상태와 경계

검색 전, 조회 중, 결과 0건, 성공, 색인 대기와 오류를 구분한다. 편집 중 조건과 성공 결과에 적용된 조건을 별도로 표시한다. 실패하면 이전 결과·상세·적용 조건을 보존하고 재시도는 실패했던 조건을 그대로 사용한다. 모드 변경은 진행 중 요청을 취소하고 늦은 응답은 폐기한다.

색인 대기·재시도 수는 전체 작업 큐의 관측치이며 해당 검색의 누락 수가 아니다. 대기 0건도 검색 완전성을 보장하지 않는다. SEARCH_UNAVAILABLE, SEARCH_INDEX_REBUILDING, SEARCH_CAPACITY_EXCEEDED, STORAGE_UNAVAILABLE과 필드 검증 오류를 구별해 안내한다.

초기 검색은 최신 50건이다. truncated이면 일부 결과라는 안내를 제공한다. 커서 API가 없어 무한 스크롤이나 과거 전체 탐색은 구현하지 않는다. 새 로그 알림과 실시간 목록 움직임 개선도 이번 범위에서 제외한다.

## 시간 제한과 검증

검색 서버 중계는 15초, 브라우저는 18초로 시작한다. 백엔드가 색인 식별 확인·실제 검색·식별 재확인의 ES 요청 세 번을 순차 실행하므로 기존 일반 조회의 시간 제한을 그대로 적용하면 정상 요청을 먼저 끊을 수 있다. 이는 SLA가 아니라 현재 백엔드 요청별 제한을 고려한 시작값이며 실제 지연 관측 후 조정한다. 기존 조회·SSE 제한은 유지한다.

응답 크기·구조·기간·정렬·중복·서버·레벨·색인 대기 수의 정합성을 검사한다. 브라우저 검증은 조건 편집, 모드 전환, 취소, 오류 보존, 초점, 모바일과 안전한 텍스트 출력을 확인한다. 격리된 실제 MySQL·ES·Spring Boot·Next.js 검증은 분석 검색과 필터, 상세, ES 장애 중 저장·실시간 유지, 복구 및 51건 중 50건 표시를 확인한다. 사용자 개발 서버와 데이터를 사용하지 않는다.

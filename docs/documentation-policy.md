# Markdown 문서 보존과 정책 기록 규칙

2026-10-27 사용자 요청으로 적용한다. 사용자가 작업 내용과 결정 이유를 직접 읽고 학습·정리할 수 있도록 Markdown 문서를 지속적으로 보존한다. 모든 분야의 문서 작업에 적용한다.

## 기존 문서 보존

- 기존 `.md` 문서는 삭제하지 않는다. 초안이 확정되거나 정책이 대체되어도 파일을 보존한다.
- 기존 정책의 일부가 바뀌면 해당 문서를 수정한다. 관련 없는 설명이나 결정 근거까지 지우거나 문서 전체를 불필요하게 덮어쓰지 않는다.
- 더 이상 적용하지 않는 내용은 현재 정책과 혼동하지 않도록 대체됨 또는 적용 종료 상태, 변경 이유와 후속 문서 링크를 표시한다.
- 내용을 다른 문서로 옮기더라도 기존 파일을 삭제하지 않고 이동 이유와 새 위치를 안내한다.

## 새로운 정책 기록

- 기존 정책의 부분 수정이 아니라 완전히 새로운 정책이 추가되면 별도의 Markdown 문서를 만든다.
- 기존 문서와 관련이 있으면 서로 링크하고, 반복해서 지켜야 하는 공통 규칙은 루트 AGENTS.md에서 새 문서를 안내한다.
- 파일이 늘어난다는 이유로 기존 문서를 삭제하거나 서로 다른 정책을 하나로 합쳐 원래 설명을 없애지 않는다.

## 사용자가 이해할 수 있는 설명

- 정책의 목적, 필요한 이유, 실제 적용 방법과 관련 예시를 이해하기 쉬운 말로 설명한다.
- 정책 변경 시 변경일, 바뀐 내용과 이유를 해당 문서에 남긴다. 이전 결정의 의미를 이해하는 데 필요한 근거를 보존한다.
- 제안, 확정된 명세와 실제 구현·검증 결과를 구분한다. 새로운 명세 합의가 기능 구현 승인이나 검증 완료를 뜻하지 않는다.
- 문서 수정·추가를 보고할 때는 사용자가 직접 읽을 수 있도록 파일 링크와 핵심 변경 내용을 제공한다.
- 영역별 학습 문서는 [공통 기록 형식](learning-record-format.md)에 따라 상단의 주제·시간·간략한 내용 목차와 아래 상세 기록을 함께 누적한다. 새 작업은 검증·커밋 완료 후 기능·기술 내용과 이유를 기록하고 PR·CI 절차 이력은 제외한다. 기존 설계 설명은 구현 완료와 구분해 보존한다.

예를 들어 로그 조회의 기본 기간 변경은 기존 조회 명세를 수정하고 이유를 기록한다. 새로운 로그 보존·삭제 정책을 도입하면 별도의 정책 문서를 만들며, 관련 조회 명세에서 그 문서를 연결한다. 이 예시는 정책 기록 방식의 설명이며 로그 보존·삭제 기능의 도입을 확정하는 것은 아니다.

# 영역별 Git 브랜치 이름 규칙

2026-10-27 사용자 요청으로 새 브랜치 이름에 영역을 표시한다. 브랜치 이름만 보고 어느 영역의 어떤 작업인지 파악하기 위한 규칙이다.

## 이름 형식

`codex/<영역>/<작업명>`을 사용한다.

| 영역 | 접두사 | 예시 |
| --- | --- | --- |
| 백엔드 | codex/backend/ | codex/backend/log-ingestion |
| 프론트 | codex/frontend/ | codex/frontend/log-list |
| 디자인 | codex/design/ | codex/design/log-detail |
| 인프라 | codex/infra/ | codex/infra/compose-setup |

인프라의 접두사는 infrastructure의 일반적인 축약인 `infra`를 사용한다. 작업명은 작업 내용을 나타내는 짧은 영문 소문자와 하이픈으로 작성한다.

## 적용 범위

- 앞으로 생성하는 브랜치에 적용한다. 이미 작업 중인 브랜치는 이름을 바꾸거나 강제 푸시하지 않고 계속 사용할 수 있다.
- 여러 영역에 걸치는 작업은 주 담당 영역을 기준으로 정한다. 공통 정책·저장소 운영 문서는 기본적으로 infra 영역으로 분류하고, 특정 분야의 문서는 해당 분야를 사용한다. 사용자가 별도로 지정한 영역이 있으면 그 지정을 따른다.
- 같은 기능을 이어 작업할 때는 기존 브랜치·worktree 재사용 원칙을 유지한다. 이름 통일을 이유로 불필요한 브랜치를 만들지 않는다.
- 최신 main 기준, 기능 단위 작업, 전체 검증과 PR 병합 등 기존 작업 규칙은 유지한다.

## 변경 기록

- 2026-10-27: 기존의 codex/ 접두사만 사용하던 규칙을 codex/ 뒤에 backend·frontend·design·infra를 붙이는 형식으로 구체화했다. 기존 브랜치와 과거 문서의 예시는 당시 기록으로 보존한다.

- 2026-10-27 후속 정정: 최초 요청의 infla는 오타로 확인돼 infra로 수정했다. 모든 새 인프라 브랜치는 codex/infra/를 사용한다.

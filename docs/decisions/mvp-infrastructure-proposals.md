## 확정 기준과 제안의 경계

- 초기 세팅·GitHub·CI·main 보호는 PR #4·#5와 병합 main CI 확인으로 충족했다. [설정 기록](../setup-status.md)을 근거로 유지한다. Next SSR 실행·검증 완료나 운영 배포 완료를 뜻하지 않는다.
- Java 25·Spring Boot 4.1.2·MySQL 8.4.13 LTS·Gradle 9.8.2 Wrapper는 유지한다.
- TypeScript·Next.js SSR·npm·잠금 파일·npm ci·standalone은 프론트 채택 기준이다. 실제 버전 조합의 설치·호환성은 미검증이며 Gradle/npm 공통 역할 규칙은 추가 합의가 필요하다.
- 수집 단건 256 KiB, WAS 보관 100건 또는 8 MiB, 단일 작업자·동시 1건, 연결 1초·시도 전체 3초, 최초 포함 최대 3회, 종료 전송 최대 5초는 기존 승인 초기값이다.
- 커서 4,096 ASCII 문자·수명 30분·HMAC-SHA256 서명은 기존 승인 기준이다.
- 아래 값은 위 확정 사항을 제외하면 모두 합의용 제안이다. 구현은 별도 요청 후 시작한다.

## 설정 주입과 캐시 제안

- 서버 전용 LOGSCOPE_API_BASE_URL 또는 LOGSCOPE_API_BASE_URL_FILE 중 하나를 사용한다. 둘 다 지정하거나 둘 다 없으면 시작 실패로 처리한다. 설정 누락·우선순위 혼동을 방지하기 위한 제안이며 변수명을 확정한 것은 아니다.
- NEXT_PUBLIC 접두사·브라우저 번들·HTML·오류에 내부 주소를 포함하지 않는다. 문서에는 Compose 예시만 사용하고 실제 운영 주소·비밀값은 저장하지 않는다.
- 기존 채택 기준인 fetch cache: no-store와 동적 렌더링을 유지하고 HTML·조회 응답 Cache-Control: no-store를 확인한다. 로그 ISR·공유 데이터 캐시는 사용하지 않는다. 해시 정적 JS·CSS 캐시는 허용하는 안이다.
- 로컬 MVP에 별도 프록시는 우선 추가하지 않는다. 운영 프록시·TLS·인증과 배포는 별도 설계·승인 범위다. 향후 프록시도 HTML·조회 캐시 비사용과 SSR 스트리밍을 방해하지 않아야 한다.

## GET 중계와 오류 제안

GET /api/logs와 /api/logs/{eventId}만 고정 Spring API에 연결한다. 임의 URL·수집 POST는 제공하지 않고 나머지 메서드는 405로 처리한다. 명세 쿼리만 허용하며 중복·미지 쿼리는 400, 리다이렉트는 따라가지 않는 안이다. SSR과 중계는 같은 서버 전용 클라이언트를 사용한다.

| 상황 | 추천 HTTP/code | 이유 |
| --- | --- | --- |
| 연결 실패 | 502 UPSTREAM_UNAVAILABLE | 연결 불가와 API의 유효한 오류 구분 |
| 비JSON·잘못된 성공/오류 응답 | 502 UPSTREAM_INVALID_RESPONSE | 빈 목록 성공으로 위장하지 않음 |
| 크기 초과 | 502 UPSTREAM_RESPONSE_TOO_LARGE | 원문 절단 없이 안전하게 실패 |
| 전체 기한 초과 | 504 UPSTREAM_TIMEOUT | 유한 시간 내 실패 안내 |

새 code는 제안이며 백엔드·프론트와 확정해야 한다. application/problem+json으로 안전한 설명·code·허용 errors만 반환한다. 유효한 백엔드 상태·code·errors·Retry-After를 보존하되 원문 HTML·SQL·내부 주소·stack trace나 모든 헤더를 그대로 전달하지 않는다. 허용 상태·필드·Retry-After 파싱·길이 한도는 명세화해야 한다. 조회 자동 재시도는 0회 제안이며 WAS 전송 재시도와 구분한다. 인증 전달은 MVP에서 없으며 향후 별도 합의한다.

## 크기 제한 제안과 계산 근거

본문 상한은 압축 해제 후 읽은 실제 바이트 기준이다. Content-Length만 믿지 않고 스트림을 읽으며 누적 제한을 적용하는 안이다. 초과 시 읽기를 취소하고 정상 JSON으로 자르거나 빈 성공으로 바꾸지 않는다.

| 대상 | 추천값 | 이유 |
| --- | --- | --- |
| 수집 요청 | 기존 256 KiB 유지 | 승인 기준. 압축 수집 요청 미지원 유지 |
| 목록 응답 | 8 MiB | 100건 × message 4,096 코드 포인트 × 보수적 JSON escaping 최대 12바이트는 약 4.69 MiB. 메타데이터·커서 여유 포함 |
| 상세 응답 | 1 MiB | message·exception 합계 36,864 코드 포인트의 escaping과 메타데이터 여유 |
| 오류 응답 | 64 KiB | 오류 자체의 과도한 메모리 사용 제한 |
| 경로+쿼리 | 16 KiB | 커서 4,096자·키워드 percent encoding·나머지 조건 여유 |
| 요청 헤더 | 총 32 KiB | 일반 헤더와 요청 라인 처리의 계층 차이를 고려한 여유. URL 제한과 실제 HTTP 서버의 계산 범위 대조 필요 |
| SSR HTML | 32 MiB 검증 예산 | JSON 직렬화·HTML escaping·마크업 증가량 고려 |

KiB=1,024 bytes, MiB=1,048,576 bytes다. 최대 길이 Unicode·제어문자·JSON escaping과 양쪽 커서를 포함한 직렬화 경계 데이터를 만들어 모든 계층이 유효한 최댓값을 수용하는지 확인한다. 목록은 exception을 포함하지 않는다. SSR HTML은 스트리밍 시작 후 안전한 오류로 바꾸기 어려우므로 32 MiB를 우선 검사 예산으로 두고 출력 실측 후 제한 방법을 합의한다. 유효 응답이 실패하면 원문을 자르지 않고 상한·표현 방식을 조정한다.

## WAS 진단 제안

수집 대상에서 제외한 구조화 진단을 우선 사용하고 별도 관리 포트·대시보드는 추가하지 않는다. 10초마다 요약하고 정상 종료 시 최종 요약을 기록하는 안이다. 진단 폭증·순환 전송을 피하기 위한 선택이다.

- 기존 generated·enqueued·queueRejected·sendAttempts·failedAttempts·acknowledged·abandoned·queueDepth를 유지하고 보관 bytes·진행 중 건수를 추가 제안한다.
- instanceId·제한된 실패 원인으로만 구분하고 eventId·message·exception·커서·키는 진단에 포함하지 않는다.
- 누적값은 재시작 시 초기화한다. queueRejected와 최종 abandoned는 관측 가능한 전달 포기이며 실제 미저장 건수와 같지 않다.
- 실패 시도와 shutdownPending을 abandoned에 다시 더하지 않는다. 정상 종료 잔여 이벤트는 shutdown 원인으로 abandoned에 포함하되 shutdownPending은 같은 건수를 설명하는 별도 관측값이다.
- JSON 필드명·실패 원인 enum·bytes 계산 범위·재시작 식별·최종 기록 유실 시 한계는 백엔드와 확정한다.

## 성능·장애·종료 검증 제안

| 항목 | 추천 시작 기준 | 이유 |
| --- | --- | --- |
| 기능 사례 | 최소 51건, 세 WAS·동일 시각·오류·길이 경계 | 50건 페이지 경계와 공통 기능 확인 |
| 성능 데이터 | 10만 건, 최근 24시간·세 WAS 혼합 | 제한된 개발 규모의 검색 비용 확인 |
| 데이터 크기 | 일반 message 약 1 KiB, ERROR 10%, exception 약 8 KiB | 일반 로그와 예외 혼합. 최대 길이 검증은 별도 |
| 전송 부하 | WAS당 이벤트 1건/초, 10분 | 단일 작업자 MVP의 낮은 시연 부하 시작점 |
| 조회 부하 | 동시 사용자 3명, 10분 | 소규모 동시 탐색 확인 |
| 응답 목표 | 목록 p95 2초 이하·상세 p95 1초 이하 | 초기 통과 목표이며 실측 SLA 아님 |
| 환경 | 준비된 데이터 포함 4 CPU·8 GiB 환경, 서비스별 CPU·메모리 기록 | 결과 해석에 필요한 환경 고정. 전체 실행 환경 기준이며 컨테이너별 할당은 미결정 |
| 정상 부하 | 전달 포기·예상 밖 오류 0건·중복 저장 0건 | 정상 입력의 기본 성공 확인 |
| 장애 | 수집기 60초 중단·지연·429/503·DB 실패·대기열 포화 | 요청 처리 유지·한도·재시도·집계 확인 |
| 종료 | 전송기 5초 기한, 컨테이너 10초 내 종료 | 기존 승인값과 외부 유예 확인 |

1건/초는 업무 요청마다 로그 한 건인 합성 부하를 뜻한다. 장애 중 전달 포기는 허용하되 WAS 업무 요청이 수집기 장애로 실패하지 않고 메모리 한도·집계가 유지되는지 확인한다. WAS의 8 MiB는 직렬화 보관 한도이며 전체 JVM 힙 한도가 아니다.

구현 전 검색 조건별 분포·워밍업·측정 경로(직접 API/중계/브라우저)·표본 수·메모리 통과값·자원 배분과 업무 요청 지연 허용치를 합의해야 한다. 51건을 성능 근거로 사용하거나 미측정 수치를 달성했다고 표시하지 않는다.

## 합의 담당과 적용 순서

1. 총괄·프론트·인프라: Gradle/npm 역할, 버전·UI 도구와 전체 검증 정책.
2. 프론트·인프라: 포트·이미지·health·시작 대기·주입·캐시·종료.
3. 백엔드·프론트·인프라: 중계 오류·응답/URL/헤더 상한·기한·취소.
4. 백엔드·인프라: 키 회전·진단·성능/장애/종료 기준. 화면 복구는 프론트·디자인과 연결.
5. 총괄 합의 후 기존 명세에 변경일·내용·이유를 기록하고 새로운 정책은 별도 문서로 연결한다. 구현·설치·실제 검증은 별도 요청 후 진행한다.

## 참고 근거와 한계

- [Playwright CI](https://playwright.dev/docs/ci): CI worker 1개 권고와 브라우저 의존성 설치 안내. 재시도 0회·기한·보관 기간은 본 인프라 제안이다.
- [Next 자체 호스팅](https://nextjs.org/docs/app/guides/self-hosting): 운영 프록시·캐시·스트리밍 고려사항. 로컬 구성이나 수치를 보증하는 자료는 아니다.
- [Node HTTP](https://nodejs.org/api/http.html): 헤더·수신 기한과 HTTP 서버 제한의 구분. 채택할 Node 버전·Next standalone에서 실제 제어 가능한 항목은 구현 때 재확인한다.

본 문서는 채팅에서 제시한 값과 이유를 보존한 제안이다. 지원 버전·보안·호환성·수치의 타당성을 새로 실행 검증한 결과는 아니다.

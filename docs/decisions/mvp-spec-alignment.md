# MVP 명세와 화면 합의

2026-10-27 사용자 승인. 아래 조정안을 분야별 명세와 화면의 공통 기준으로 사용한다. 기능 구현 승인은 아니며, 구현은 선행조건 충족과 별도 요청 후 시작한다.

## 확정한 기준

| 항목 | 합의 |
| --- | --- |
| API | /api/v1/logs의 HTTP 수집·목록 및 /api/v1/logs/{eventId} 상세. JSON 성공 응답과 application/problem+json 오류, 필드·중복·오류 규칙은 API 명세 기준 |
| 시간 | UTC Z 표기, 밀리초 저장·응답·목록·상세·입력. 시작 포함·종료 제외이며 from < to |
| 기본 조회 | 화면은 최근 15분, 전체 서버·레벨, 빈 키워드. 명시적 from/to를 전송 |
| 새로고침 | 최근 15분은 실행 시점에 경계를 재계산. 절대 시간은 유지. 미적용 입력은 보존 |
| 페이지 | 커서 기반 이전·다음, 기본 50건. 번호 이동·총 건수·총 페이지 없음. occurredAt DESC, eventId DESC |
| 조회 일관성 | 페이지 탐색 동안 시간·검색 조건을 고정. 완전한 스냅샷은 보장하지 않으며 뒤늦게 수집된 로그는 새로고침으로 확인 |
| 상세 상태 | 조건 적용·초기화·페이지 이동·새로고침 성공 시 해제. 실패 시 기존 목록·상세·적용 조건 유지 |
| 목록 | 시각·레벨·서버·메시지가 기본 열. serviceName은 상세. hasException은 작은 텍스트·아이콘 표시로 제공하며 색상만 사용하지 않음 |
| 상세 형태 | 넓은 화면은 비모달 우측 패널, 좁은 화면은 목록 아래 상세. 원문 개행·줄바꿈 전환·복사와 키보드 접근 지원 |
| 서버 선택지 | was-1, was-2, was-3을 설정값으로 제공. 현재 페이지에서 추출하지 않으며 별도 메타데이터 API는 추가하지 않음 |
| 검색 | message의 대소문자를 구분하는 리터럴 부분 검색. 앞뒤 공백 제거, 1~200자. %, _도 문자로 처리. exception 검색 제외 |
| 식별·중복 | eventId를 상세 조회와 중복 판정에 사용. 같은 내용 재전송은 성공, 다른 내용은 409 충돌 |
| 원문 제한 | 길이·본문 크기 초과는 거절하고 저장된 원문을 자르지 않음. 요약은 화면에서만 수행 |
| 실패 관측 | WAS별 진단 지표로 확인. 시도 실패와 이벤트 전달 포기를 구분하며 별도 운영 화면은 추가하지 않음 |

커서 세부 표현과 검증 정책은 백엔드의 후속 사용자 승인으로 확정했으며 아래 추가 기준과 API 명세를 따른다. 페이지 이동 시 현재 화면 경계의 시각·eventId를 기준으로 탐색하고, 필터나 크기 변경 및 새로고침은 커서를 제거해 첫 목록부터 조회한다. 커서는 클라이언트가 해석하지 않는 값이며 일관된 필터와 함께 사용한다.

## 공통 합성 검토 사례

기준 오류 이벤트는 serviceName=sample-was, instanceId=was-2, eventId=7b2a8c30-8d94-4d5f-a6d8-931cf6a6a101, occurredAt=2026-10-27T03:00:00.123Z, level=ERROR, message=Synthetic failure for logscope demo로 통일한다. API 명세의 예외 문자열을 함께 사용한다.

was-1·was-3 정상 INFO, exception=null인 로그, 동일 시각·다른 eventId, 긴 메시지·예외, 빈 결과, 목록·상세 실패, 상세 404와 지연 응답도 함께 검토한다. 길이 초과는 저장 거절, 대소문자가 다른 키워드는 불일치, 중복 재전송은 한 건 유지로 확인한다. 같은 합성 사례를 문서·화면·향후 테스트에서 공유하며 지금 테스트 코드를 작성하지 않는다.

## 후속 승인으로 확정된 세부 기준

2026-10-27 각 분야의 사용자 승인 기록을 취합했다. 자세한 자료형·오류·정규화 규칙은 [백엔드 API 명세](../contracts/log-api-draft.md), 화면 복구는 [프론트 연동 명세](../contracts/frontend-integration-draft.md)를 따른다.

| 항목 | 최신 확정 내용 |
| --- | --- |
| 조회 기간 | from/to 모두 필수, 시작 포함·종료 제외, from < to, 최대 24시간. 정확히 24시간 허용. 보존 기간 제한과는 별개 |
| 커서 방향 | next는 더 오래된 로그, previous는 더 최신인 가까운 로그. 응답은 항상 occurredAt DESC, eventId DESC. 해당 방향 결과 없으면 null, 빈 결과는 양쪽 null |
| 커서 보호 | 버전·방향·경계·조회 조건 식별값·발급/만료를 담은 base64url JSON과 HMAC-SHA256 서명. 클라이언트는 해석하지 않음. 최대 4,096 ASCII 문자 |
| 커서 수명 | 최초 탐색 후 30분, 이후 커서도 같은 만료 유지. 무효·만료·조건 불일치는 각각 INVALID_CURSOR·CURSOR_EXPIRED·CURSOR_QUERY_MISMATCH의 400 오류 |
| 전송 보관 | WAS별 대기·진행 중·재시도 포함 100건 또는 직렬화 UTF-8 본문 합계 8 MiB 중 먼저 도달하는 한도. 단건 256 KiB. 전체 JVM 힙 상한은 아님 |
| 전송 실행 | 비동기 단일 작업자·동시 1건. 포화 시 새 이벤트 즉시 거절하고 queueRejected 집계 |
| 타임아웃 | 연결 1초, 시도 전체 3초 |
| 재시도 | 최초 포함 최대 3회, 대기 0~500ms·0~1초 균등 무작위. 네트워크·타임아웃·500/502/503/504/429 대상. 동일 eventId·본문 유지 |
| Retry-After | 전송기의 429/503에서 유효한 대기를 존중. 남은 대기가 3초 초과면 단축 재시도하지 않고 전달 포기 |
| 정상 종료 | 접수 중단 후 최대 5초 전송, 이후 취소·남은 건수 보고. 영속 대기열과 재시작 복구 없음 |
| 전달 관측 | 시도 실패와 이벤트 전달 포기 구분. 타임아웃 포기는 실제 미저장과 같지 않음. shutdownPending과 abandoned를 중복 합산하지 않음 |
| 화면 복구 | 실패 재시도는 실패한 절대 시간·필터·커서 유지. 커서 오류는 기존 결과를 보존하고 커서만 제거하는 수동 복구. 자동 대체 조회·자동 재시도 없음 |
| 입력·응답 | 공백 키워드는 제거 후 파라미터 생략. 잘못된 성공 응답·비JSON 오류는 빈 성공으로 처리하지 않음. 미지의 level은 원문 텍스트로 표시하고 선택지에 추가하지 않음 |

전송 수치는 승인된 MVP 초기값이며 성능 검증 결과는 아니다. 선택 이유는 탐색 위치 이동 방지, 무제한 검색 방지, WAS 자원·종료 지연 제한이며 자세한 근거는 API 명세에 보존한다.

## 기능별로 진행할 분야 간 합의

추천안·이유·담당·확인 기준은 [MVP 추가 합의 검토안](mvp-cross-area-proposals.md)에 정리한다. 해당 문서의 제안은 이 문서의 확정 기준과 구분한다. [기능 단위 개발 방식](../feature-development-workflow.md)에 따라 현재 기능에 필요한 것만 착수 전에 결정하며 모든 제안을 선행조건으로 삼지 않는다. 기능 구현은 별도 요청 전까지 시작하지 않는다.

## 이전 검토 기록

- 브랜치 보호 해결과 실제 적용 확인은 인프라 채팅에서 진행한다. 이 문서로 완료 처리하거나 기존 선행조건을 완화하지 않는다.
- 프론트 프레임워크·빌드·개발 서버·API 연결 환경은 프론트 채팅에서 정의한다.
- API의 시간 조건 생략 허용 여부와 최대 조회 기간, 커서 인코딩·방향·응답 필드·만료·잘못된 커서 처리 등 세부 명세는 구현 전에 정한다. offset 방식은 채택하지 않는다.
- 전송 대기열 100건, 연결 1초·전체 3초 타임아웃, 최대 2회 재시도는 검증 전 수치 제안으로 유지한다. 대기열 byte 상한, 진행 중 이벤트 포함 여부, 종료 처리, 지표 노출 방식과 검증 데이터 양도 구현 전 확정한다.
- 요청 256 KiB 제한과 필드별 문자 제한은 함께 적용한다. JSON 인코딩 후 본문이 크기 제한을 넘으면 문자 제한 이내여도 거절한다.
- 브랜치 보호나 프론트 환경 외의 남은 세부사항은 각 담당이 구체화해 총괄에서 조율하며 임의로 구현을 시작하지 않는다.

위 이전 검토 기록은 최초 조율 당시의 상태다. 브랜치 보호, 프론트 선택, 조회·커서·전송 항목의 미결정 표시는 위 후속 승인 기준으로 대체한다. 지표 노출·키 관리·공통 검증 등은 추가 합의 대상으로 유지한다.

## 변경 기록

- 2026-10-27: 백엔드 세부 승인과 프론트 채택 기준, 인프라 선행조건 충족 근거를 공통 기준에 반영했다. 기존 미결정 기록은 판단 과정을 이해할 수 있게 이전 기록으로 보존했다. 확정 초기값과 실행 검증을 구분하고 새로운 SSR 구조와 추가 합의 제안은 별도 문서로 연결했다. 기능 구현·배포·커밋은 수행하지 않았다.

- 2026-10-27 후속 변경: 기능 단위 진행 방식과 Gradle/npm 역할·전체 검증 유지 원칙을 공통 기준에 반영했다. 기존 명세와 승인 초기값은 유지하며 필요한 세부 결정을 해당 기능 시점으로 나눴다.

## 2026-10-27 파일 수집 후속 승인

사용자가 샘플 WAS 두 대의 60초 랜덤 로그·수동 버튼·Logback 파일·Vector 배치 전송 구현을 요청했다. 이번 기능은 기존 내부 메모리 대기열·단건 직접 전송 대신 [샘플 파이프라인](../sample-log-pipeline.md)의 한도·재시도·부분 실패 기준을 적용한다. 파일과 전송을 분리해 WAS가 중앙 API 장애에 직접 의존하지 않게 하고 요청 수를 줄인다. Kafka와 세 번째 WAS·운영 무손실 수집은 후속 검토다. 조회·커서 기준은 이번 변경 대상이 아니다.

# 영역별 학습 기록 공통 형식

2026-10-27 사용자 요청으로 백엔드 학습 문서의 누적 방식을 모든 영역에 적용한다. 학습 문서는 기능을 만들면서 무엇을 요청했고 왜 선택했으며 실제 무엇을 확인했는지 시간순으로 설명한다. 이 형식은 기능 구현 승인이 아니다.

## 적용 문서와 정렬

docs/learning/frontend.md, design.md, backend.md, infrastructure.md에 적용한다. 각 파일 최상단은 문서 제목, 짧은 안내, 기록 목차 순서다. 목차 열은 **주제 / 시간(KST) / 간략한 내용**으로 통일하며, 주제는 아래 상세 기록으로 연결한다.

목차 행과 상세 기록 모두 오래된 것부터 새로운 것 순서로 추가한다. 최신 항목은 목차의 마지막 행과 본문 맨 끝에 쌓인다. 시간은 Asia/Seoul 기준 YYYY-MM-DD HH:mm KST로 기록한다. 과거 시각을 모르면 날짜와 작성 시각 미기록을 표시하고 추정하지 않는다. 같은 날짜 안에서 정확한 순서를 확인할 수 없는 기록은 기존 순서를 보존한다.

기록 시간은 해당 내용을 기록한 시점이다. 구현·검증·병합 시간이 다르면 본문에 따로 표시한다. 같은 기능을 이어 작업해도 의미 있는 구현·결정 변경·검증·병합 결과가 생기면 새 항목으로 남기고 이전 항목을 연결한다. 작업 진행과 중단도 상태에 맞게 적으며 확인하지 못한 결과를 완료로 쓰지 않는다.

실제 만든 것과 달라진 동작, 데이터 흐름·파일·쉬운 예시. 문서만 썼으면 명시.

## 기록 보존과 적용 방법

### 반드시 새 항목을 추가하는 변경

각 영역에서 새로운 기능을 구현하거나 기술적으로 수정·추가·제거·대체하면 변경 규모와 관계없이 목차 행과 상세 기록을 반드시 함께 추가한다. 같은 기능의 후속 기술 수정도 기존 기록에 덮어쓰지 않고 새 항목으로 남긴다.

| 기록 대상 | 예시 |
| --- | --- |
| 제품 기능과 동작 | API 추가, 검색 조건 변경, 화면 상태·상세 복구 동작 수정 |
| 데이터와 처리 방식 | migration·인덱스, 중복 처리, 커서·대기열·재시도 방식 변경 |
| 기술 구성 | 의존성 버전 추가·갱신·제거, 빌드·테스트·CI·Docker·실행 설정 변경 |
| 안전성과 운영 | 보안·권한·비밀 주입·관측·성능·배포·복구 방식 변경 |
| 기술적 설계 결정 | 명세·아키텍처·접근성 동작 등 구현 기준의 확정이나 변경. 구현 전이면 결정만 한 상태로 기록 |

오탈자, 공백, 서식 정리와 깨진 링크 보정처럼 기능·기술적 의미가 달라지지 않는 변경은 새 기록을 생략할 수 있다. 작은 한 줄 수정도 타임아웃·권한·의존성·동작을 바꾸면 단순 변경이 아니다. 판단이 애매하면 기록한다.

여러 파일이 같은 목적의 한 작업이면 하나의 주제로 묶되 변경 이유와 영향을 빠뜨리지 않는다. 일부만 구현하거나 검증이 막혔으면 그 상태까지 기록하고, 이후 해결·검증 결과는 새 항목에서 이전 기록과 연결한다. 새 기록을 추가하라는 규칙은 기능 착수·실행 승인 범위를 확대하지 않는다.

### 기존 기록 보존

- 새로운 기능·의미 있는 작업 결과를 보고할 때 담당 영역 문서의 목차 행과 상세 기록을 함께 추가한다. 다른 영역의 문서를 동시에 수정하지 않는다.
- 기존 기록 내용·출처·시각을 지우거나 과거 결과를 현재 결과로 덮어쓰지 않는다. 정정은 새 기록에 이유와 이전 기록 링크를 남긴다. 오탈자·링크 보정은 가능하다.
- 이번 통일 이전의 상세 설명은 이전 기록으로 보존한다. 과거 글을 억지로 여섯 항목에 끼워 맞춰 출처나 결과를 잃지 않는다. 새 기록부터 여섯 항목을 동일하게 사용한다.
- 주제 ID는 파일 안에서 유일하고 제목이 수정돼도 링크가 유지되도록 명시한다. 같은 기능 후속 기록은 별도 ID를 사용한다.
- 간략한 내용에는 구현·문서·검증·병합·중단 등 상태를 함께 적는다. 길고 상세한 설명은 본문에 둔다.
- 비밀값·실제 고객 정보는 쓰지 않는다. 문서 작성만으로 커밋·기능 구현·배포를 시작하지 않는다.

## 변경 기록

- 2026-10-27: 영역별로 달랐던 학습 기록을 백엔드의 목차·주제·시간·상세 누적 방식에 맞췄다. 사용자 요청에 따라 목차의 상태 열은 간략한 내용 열로 통일하고 상태도 요약에 포함한다. 기존 기록은 보존하고 이후 추가할 상세의 공통 여섯 항목을 정했다.
- 2026-10-27 후속 요청: 새 기능과 기술적 수정·추가는 항상 새 항목으로 기록하도록 의무화했다. 단순 오탈자·서식 정리와 기술적 의미가 바뀌는 변경을 구분하고, 작은 수정이나 동일 기능의 후속 작업도 누락하지 않도록 예시를 추가했다.

# 프론트 최소 목록·상세 API 연결

2026-10-27 사용자 요청에 따른 최소 연결 구현이다. 검색·필터·커서 UI와 서버 기능은 추가하지 않는다. [API 명세](contracts/log-api-draft.md), [연동 명세](contracts/frontend-integration-draft.md), [공통 아키텍처](architecture.md)의 승인 기준을 사용한다.

## 사용자가 확인할 흐름

브라우저의 첫 요청에서 Next.js가 최근 24시간의 절대 UTC from/to를 한 번 계산하고 Spring Boot GET /api/v1/logs를 size=50으로 직접 조회한다. 첫 HTML에 실제 목록과 범위·성공 시각을 포함하며 hydration만으로 다시 조회하지 않는다. 상세 보기는 같은 출처의 GET /api/logs/{eventId}를 거쳐 저장된 원문을 읽는다. 서비스·서버·시각·레벨·이벤트 ID·전체 메시지·stack trace를 표시한다. 예외 없음은 exception=null일 때만 표시한다.

검색 입력·서버/레벨/시간 필터·커서/페이지 버튼은 없다. 새로고침은 최근 24시간을 새로 계산하고, 실패 재시도는 실패한 절대 범위를 유지한다. 로그 발생 시각이 최근 24시간 밖이면 이번 화면에는 나타나지 않는다. 수집 시각이 아닌 occurredAt 기준이다. 최소 백엔드가 50건 초과에 반환하는 501 PAGINATION_NOT_IMPLEMENTED는 제한 안내로 보여주며 빈 목록으로 숨기지 않는다.

## 서버 전용 설정과 실행

LOGSCOPE_API_BASE_URL 또는 LOGSCOPE_API_BASE_URL_FILE 중 하나만 설정한다. FILE은 origin 문자열을 담은 외부 파일이다. 형식은 http/https origin이며 사용자정보·쿼리·fragment·별도 경로는 허용하지 않는다. 설정은 요청 시 읽어 빌드에 실제 주소를 넣지 않는다. 누락·충돌·잘못된 설정은 안전한 API_CONFIGURATION_ERROR와 503으로 처리하고 UI에서는 연결 설정 안내를 표시한다. live 응답은 자체 생존만 확인하며 설정/API/DB 준비 완료를 뜻하지 않는다.

Compose의 로컬 예시 origin은 http://app:8080이다. frontend는 app이 일시 중단돼도 실패 화면을 제공할 수 있도록 강제 depends_on을 추가하지 않는다. 운영 주소·비밀·NEXT_PUBLIC 값은 커밋하지 않는다. 인증 전 로컬·격리 환경 원칙을 유지한다.

```sh
# 프로젝트 루트: .env.example은 예시 값이다.
docker compose --env-file .env.example up --build
```

호스트 개발 서버는 예를 들어 LOGSCOPE_API_BASE_URL=http://localhost:8080 npm run dev로 실행한다. 실제 접속 정보가 필요한 환경에서는 Git 제외 외부 설정을 사용한다. 기존 로그가 오래됐다면 현재 시각의 합성 이벤트를 POST한 뒤 새로고침한다. 화면에서 로그를 생성하거나 실제 데이터를 자동으로 지우는 기능은 없다.

## 이번 단계의 중계 기준과 이유

- Next GET /api/logs는 canonical 밀리초 UTC from/to만 받으며 size=50으로 고정한다. GET /api/logs/{eventId}는 UUID v4 상세만 제공한다. 미지·중복 쿼리, 잘못된 시각/범위, 상세 쿼리는 400이다. Next의 GET 처리에 수반되는 HEAD 외의 수집 POST 중계는 없고 지원하지 않는 메서드는 405다. Spring API의 기존 명세를 변경하는 것은 아니다.
- SSR과 Route Handler가 공통 server-only 클라이언트를 사용한다. 외부 URL을 브라우저에서 받아 중계하지 않고 리다이렉트도 따르지 않는다. 주소·파일 경로·서버 원시 detail은 응답/HTML에 넣지 않는다.
- 백엔드 조회 총 기한은 본문 읽기까지 5초, 브라우저의 중계 요청은 8초다. 취소 신호를 fetch에 전달하고 늦은 상세 응답은 식별자로 폐기한다. 기한은 유한 실패 안내를 위한 시작값이며 측정된 SLA나 DB 쿼리 중단 보장이 아니다.
- 목록 8 MiB·상세 1 MiB·오류 64 KiB의 디코딩된 본문 상한을 읽는 도중 적용한다. 목록 최대 50건과 메시지 4,096 코드 포인트, 상세 예외 32,768 코드 포인트의 UTF-8/JSON escaping을 수용하는 여유 있는 유한 상한이다. 수집 단건 256 KiB를 목록 응답에 복사하지 않는다. 크기 초과는 정상 데이터를 잘라 반환하지 않는다. Next 중계 요청 URL은 8,192자로 제한한다. 커서가 포함된 전체 계층의 URL 정책은 다음 단계에서 별도 확인한다.
- 연결 실패는 502 UPSTREAM_UNAVAILABLE, 비JSON·잘못된 응답·리다이렉트는 502 UPSTREAM_INVALID_RESPONSE, 초과는 502 UPSTREAM_RESPONSE_TOO_LARGE, 자체 기한 초과는 504 UPSTREAM_TIMEOUT이다. 요청자 취소는 서버 내부에서 499 REQUEST_CANCELLED로 구분하며 정상 504로 오인하지 않는다.
- 현재 조회에서 나올 수 있는 유효한 백엔드 오류 status/code/필드 오류와 안전한 Retry-After는 보존한다. 임의의 원시 오류 문구는 전달하지 않는다. 응답 구조·eventId·UTC·길이·null을 검사하고 추가 필드는 허용한다. 다음 커서가 실제 포함되는 응답은 이번 단계에서 처리하지 않는다.
- 조회 fetch와 응답은 no-store다. 자동 재시도·ISR·공유 데이터 캐시는 사용하지 않는다. 서비스 지표·서명 키·DB·스키마는 이번 작업에서 변경하지 않는다.

## 화면 동작과 접근성

목록과 상세의 로딩·빈 결과·404·조회 실패를 구분한다. 목록 갱신 실패는 이전 성공 목록·상세·조건을 유지한다. 목록 조회 중 새 상세 선택만 제한하고 기존 상세 읽기·닫기·복사는 유지한다. 진행 중 상세를 중단했다면 재시도 가능한 상태로 표시하고 늦은 응답을 반영하지 않는다. 목록 성공 시 상세를 해제한다.

상세는 비모달이며 열기 시 제목에 초점을 주고 닫기 시 해당 목록 버튼으로 돌린다. 버튼이 없으면 목록 제목으로 이동한다. trace의 원문 줄바꿈·복사·줄바꿈 전환을 제공하며 HTML은 텍스트로 표시한다. 1,200px 미만은 하단 상세로 구성하고 표는 이름 있는 내부 스크롤 영역으로 둔다. 이는 최소 화면 시작 규격이며 전체 접근성 인증이나 최종 디자인을 뜻하지 않는다.

첫 SSR은 제한된 서버 조회가 끝난 HTML을 전달한다. route-level loading 스트리밍 경계를 쓰면 JavaScript를 끈 브라우저에서 결과가 숨겨지는 현상을 실제 확인해 이 경계는 넣지 않았다. 첫 응답 대기는 브라우저의 탐색 진행으로 표현하며, 응답 후의 목록·상세 요청은 화면 상태로 알린다. 전체 페이지 전달 자체의 네트워크 실패는 브라우저 재진입이 필요할 수 있고 같은 시간 범위를 보장하지 않는다.

## 검사와 범위

./scripts/verify.sh는 기존 모든 검사를 유지한다. 제어 가능한 HTTP 서버를 쓰는 Chromium 검사에서 SSR·중복 첫 조회 없음·HTML 안전 출력·상세·키보드/초점·복사·모바일·빈 결과·같은 조건 재시도·기존 상세 보존·늦은 응답 폐기·중계 입력/오류/기한/크기·50건 초과를 확인한다. 이 서버는 검사 전용이며 앱의 대체 백엔드가 아니다.

양쪽 이미지를 빌드한 뒤 scripts/verify-log-view.mjs가 별도 Docker 네트워크와 임의 loopback 포트의 MySQL·Spring Boot·Next 컨테이너를 만든다. 임시 외부 파일로 격리 DB 자격정보를 주입하고 합성 한 건을 실제 POST/커밋한 뒤 JavaScript 없는 SSR 목록·브라우저 상세 원문·초점 복귀를 확인한다. 검사가 끝나면 해당 컨테이너·익명 볼륨·네트워크·임시 파일만 정리한다. 사용자 로컬 DB/볼륨에는 쓰지 않는다. Docker·브라우저·백엔드가 없거나 실패하면 검사를 생략하지 않는다.

기능 검사는 부하 성능·검색·필터·커서·운영 인증을 보장하지 않는다. PostgreSQL/H2 같은 대체 DB로 MySQL 검증을 대체하지 않는다. 프론트 연결은 실제 Spring API 구현에 맞췄으며 백엔드 코드는 수정하지 않는다.

## 2026-10-27 밝은 테마 외형 개선

사용자 구현 요청으로 기존 로그 탐색에 파란색 강조·연한 파랑 배경·흰 패널을 적용한다. 헤더는 logscope / 로그 탐색이며 서비스명은 기존처럼 상세에만 표시한다. 메뉴·사이드바·다크 모드는 추가하지 않는다. 표와 명시적 상세 버튼·최근 24시간·50건 및 SSR/API/오류/초점 동작은 유지한다.

강조 #355da5, 본문 #202a38, 보조 #526176, 배경 #f0f6fd, 흰 패널을 사용한다. 버튼 경계 #71839e와 선택 행의 왼쪽 선은 경계·선택을 더 분명히 읽기 위한 선택이다. 비조작 패널의 연한 경계와 조작 버튼의 경계를 구분한다. 최소 버튼 높이 40px, 작은 화면 16px 바깥 여백·제목/새로고침 줄바꿈을 사용한다. 표는 이름 있는 내부 스크롤을 유지하고 1,200px 미만은 상세를 아래 배치해 긴 원문 너비를 확보한다.

확정된 범위 안의 외형 선택이며 전체 접근성 인증이나 다른 브라우저 지원을 뜻하지 않는다. 긴 합성 한글·100줄 이상 trace·작은 화면·2배 확대와 기존 동작을 검토한다. 초기 합성 시안의 실제 렌더링은 이전 브라우저 정책 차단으로 확인하지 못했으며 이번 구현은 문서와 소스에서 확인한 방향을 적용한다. 검증한 실제 구현 화면과 시안의 검증 여부를 혼동하지 않는다.

# 채팅 전달 대상 확인 정책

2026-10-28 사용자 승인. 목적은 Local/worktree 이동 후 과거 채팅으로 요청이 전달되거나 보관 채팅이 재활성화되는 일을 막는 것이다. 기존 Markdown 문서와 기록은 삭제하지 않는다.

## 전송 직전 확인

1. 사용자에게 허용된 수신 영역과 공유·검토·구현 범위를 확인한다.
2. 활성 채팅 목록을 조회하고 프로젝트·역할·threadId·hostId·현재 작업 경로를 대조한다. 이름과 과거 ID는 검색 단서이며 최종 근거가 아니다.
3. 최근 기록에서 Handoff 여부와 후속 채팅을 확인한다. 이동 결과의 destinationThreadId를 기준으로 실제 대상 경로와 상태를 재확인한다. Local에 있어야 하는 역할과 정상 진행 중인 worktree 역할을 구분한다.
4. 보관되거나 이전 작업 폴더가 제거된 채팅에는 전달하지 않는다. 전송 실패를 해결하려고 보관 해제·새 채팅 생성으로 우회하지 않는다. 대상을 특정하지 못하면 이유와 필요한 확인 사항을 사용자에게 알린다.
5. 요청을 승인된 범위 그대로 보내고 수신 결과를 확인한다. 자동 공유·자동 구현을 가정하지 않는다.

## 이동과 오전송 후 처리

Handoff 후 새 ID·host·경로를 확인해 이후 전달 대상을 갱신한다. 다른 채팅에 변경을 알려야 할 때도 사용자 전송 승인 범위를 지킨다. 고정 ID를 AGENTS.md의 영구 기준으로 삼지 않는다.

오전송이 확인되면 같은 기능의 중복 착수를 막는다. 기존 변경·브랜치·worktree를 먼저 확인하고 삭제·초기화하지 않는다. 올바른 채팅에 요청을 정정할 때 구현 착수 권한까지 확대하지 않는다. 자동 승인 검토가 거절하면 우회하지 않고 허용된 정보 공유만 수행하며 제한을 설명한다.

## 변경 이유

프론트가 worktree에서 Local로 이동한 뒤 이전 ID로 전달을 시도했고, 보관 실패를 이유로 옛 채팅을 보관 해제한 사례가 반복됐다. 이는 사용자의 worktree 운용 문제가 아니라 발신 채팅의 대상 검증 누락이다. 이름 일치나 활성 상태만으로 판정하지 않고 이동 이력·실제 작업 경로를 함께 확인한다.

이번 규칙 반영은 프론트 기능 구현 승인이 아니다. 프론트 구현은 사용자가 프론트 채팅에서 직접 지시한다.
